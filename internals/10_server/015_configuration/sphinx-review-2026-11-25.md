# Sphinx review of the SPA and configuration changes

**Review date:** 2026-11-25. **Reference release:** kajenn 0.10.1, Gramlot 0.3.41 and gramlot-py-server 0.3.32. The Examples comparison includes the local system-monitor integration. This review covers the public Sphinx trees, their build entry points, and the accuracy of the chapters affected by configuration, identity, pages, binding, storage and database access. A successful Sphinx build checks publication structure; the executable checks below establish the behaviour of the new recipes.

## Reproducible publication issue

In Gramlot Examples run the two commands from `.readthedocs.yaml` in order: `python scripts/prepare_docs_dependencies.py`, then `python scripts/prepare_docs.py`. The dependency preparation builds the gallery. The second command writes the Sphinx sources, then invokes `scripts/build-docs-example.mjs` and fails inside the serverless bundle. Esbuild reports CSS imports from uPlot, xterm and Jodit with no output path configured. The failure also reproduces using Node 22.14, in the major line specified by Read the Docs. The build scripts involved are unchanged between the release and the monitor integration. Running Sphinx separately on the staged text verifies the guide and navigation; it does not produce or qualify those missing interactive exports. The outstanding check is a complete export followed by loading its generated playgrounds in a browser.

## Executable evidence

- **Core visits.** Two tabs in one cookie jar receive different page IDs. A draft survives instance recreation and is invisible in the second tab. Another visit gets 403 for the first ID. The same operations pass with one dedicated application subprocess once it has joined. The existing SPA application and registry tests also exercise password and OIDC transitions, page disposal and ownership checks.
- **One domain method, three callers.** The Gramlot workspace renders its configured label; a real page RPC, an independent typed HTTP request and MCP `tools/call` obtain the same result. The root redirect and the catalogue tool list were checked separately.
- **Two database scopes.** The same notes service can read a site default or its own `notes:default`. A synchronous handler inserts and commits; an asynchronous handler awaits the query. The separate Python job migrates an empty SQLite database and reads the committed row without starting kajenn or importing Gramlot.
- **File storage.** The export was read back from a local directory and from an S3-compatible API on a loopback emulator. Only the service endpoint and test credentials were substituted for the bucket example. Real cloud credentials, IAM policy, hosted database availability and production capacity were outside this verification.
- **Document delivery.** Verified the rendered local links and fragments on the seven new or connected kajenn pages, plus byte-for-byte agreement between all eight downloadable files and the source used in the walkthrough. No manuals were deployed.

The earlier layout and SPA proposals informed the examples. Current runtime sources and the authentication application in kajenn 0.10.1 determine the behaviour documented here. The parallel authentication refactor is not a dependency of these recipes.
